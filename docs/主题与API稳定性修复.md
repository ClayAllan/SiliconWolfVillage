# 原生主题与 API 稳定性修复（方案 A）

初次实施：2026-10-20；请求策略按 2026-10-25 当前代码校准。保留原有棋盘和游戏规则。下方“已完成的验证”为初次实施记录，端口与测试数量不是当前服务状态。

## 使用方式

右上角 `⋮ → Theme` 选择 `Light`（浅色）、`Dark`（深色）或 `System`（跟随系统）。顶部不再提供另一套独立主题下拉。原生控件与自定义圆桌共享实际原生主题；切换外观不会新建或重置对局。

已有对局需要修改模型、接口、Key、思考策略或时限时：

1. 先暂停。如果还有待收集的行动，用单步收集已完成响应，或跳过当前玩家；未结束的远端请求仍需等待。
2. 在“模型与高级设置”调整配置，再点击“应用模型设置（保持暂停）”。应用设置不发请求，并保留棋盘、角色记忆、用量和失败计数。
3. 可点击“测试连接”验证已应用配置。它只发一次最多 256 输出 Token 的短 JSON 请求，会产生实际用量，不证明完整发言或长局稳定，也不会清零熔断计数。
4. 点击继续向后推进。已记录的系统兜底响应不会重做，已经结算的投票和技能不会回滚。

## 请求策略

| 请求 | 首次输出预算 | 预算不足时的修复上限 | DeepSeek 思考设置 |
| --- | ---: | ---: | --- |
| 投票、上警、退水、警徽、解药与快速判断 | 4096 | 6144 | 默认开启、low；格式修复关闭 |
| 发言、其余技能等主行动 | 8192 | 12288 | 默认开启、low；格式修复关闭 |
| 确认、定序 | 256 | 不扩容，仍受最多两次调用限制 | 关闭 |
| 摘要 | 1200 | 不自动重复 | 关闭隐式思考 |
| 连接诊断 | 256 | 不自动重复 | 关闭隐式思考 |

每个主行动最多两次实际调用，第一次也计入上限；模型回退同样占用该上限。所有尝试、退避共用一次行动时限。只有未通过动作校验的截断输出或推理用量占满预算等预算不足情形才尝试扩大预算；完整且通过本轮动作协议与合法目标校验的 length 响应可直接接收。普通空正文不盲目扩大。格式修复关闭重复深度思考。上述参数来自当前 config.py 与 model_protocol.py，未通过真实模型长局证明最优，也不保证消除预算不足或技术失票。

自动识别只对官方 `api.deepseek.com` 开启专用字段。其他地址默认使用通用参数；中转接口需要由用户明确选择 DeepSeek 兼容能力。思考模式下不发送无效的 Temperature；只有最终 `content` 能作为行动来源，隐式思考不作为指令执行。

JSON 截断、空消息、字段类型错误、鉴权、余额、限流、连接拒绝、连接/读取超时和服务商故障分别记录。连续三个完整行动失败仍暂停；401/402/403 立即暂停，限流等待超出行动剩余时限也立即暂停。

## 用量与诊断

“API 诊断与恢复”显示错误类别、实际尝试次数、预算、完成原因、正文/推理长度及用量。诊断下载只含白名单元数据，不含 Key、完整提示词或隐式思考文本；单一视角隐藏其他席位与模型的关联。

成功、失败重试、摘要和诊断的实际用量均计入。超时无回执时显示用量待确认；晚到结果只能补记用量，不能写回行动、玩家记忆或重置健康状态。归档单独计入诊断费用，不将它们当作玩家行动成功；推理 Token 已包含在输出中，不重复加进总数。
