# Snapshot / 视角投影性能基准（2026-10-30）

> **结论：有可重现的历史规模相关开销；高频快照读取会与后台推进争抢共享锁。正常单浏览器 1.5 s 刷新频率下，当前合成测试未见严重吞吐下降。** 这是诊断报告，不是生产环境延迟承诺，也不构成部署优化。

## 读取链路性能

操作定义：

1. **Snapshot**：`GameService.snapshot()`，在服务的 `Condition/RLock` 内逐字段深拷贝引擎状态（排除模型连接与取证器）。
2. **Projection**：`project_view(snapshot.engine, viewer_seat)`，创建全知或受限视角数据，投影全部公开日志，并为可见座位复制推理记录。
3. **Pipeline**：Snapshot → Projection → `select_feed_window(..., limit=90)`。不包含 Streamlit HTML、WebSocket 传输、浏览器绘制或模型推理。

## 动态窗口选择：已确认的提前退出缺陷

[service/live_feed.py](https://github.com/ClayAllan/SiliconWolfVillage/blob/2eaf96bb75012f4f837128c96d2acf8fd37a952e/service/live_feed.py#L58-L110) 里，`selected_reversed` 仅在 `len(selected_reversed) < cap` 时追加，`len == cap` 后只设置 `truncated=True`，但跳出循环需要 `len(selected_reversed) > cap`；因此这条跳出条件永远无法成立，限量展示仍扫描整个 `rows`。

运行 B 的 feed-only 测量：100 / 1,000 / 5,000 / 15,000 条下，限量模式中位耗时分别为 **0.012 / 0.109 / 0.554 / 1.665 ms**。这个缺陷真实存在，但目前它只占整体 Pipeline 的一小部分；修复后仍然需要处理 Snapshot 与 Projection 的全量成本。

建议单独提交小 PR 修正提前退出，补齐**跟随最新、暂停跟随、未读计数、频道过滤、完整历史**等状态的回归测试；不得因加快显示而丢失未读事件或泄露视角信息。

## 后台推进竞争（合成测试）

压力源是真正的 `GameService` 自动推进线程，但引擎事件是**无网络脉冲生成器**，在 5 ms 的模拟步进间隔下，比较只推进与同时进行快照读取的吞吐率。计算包含 Python 线程调度、CPU 竞争及同一把服务锁造成的等待，**不能拆分解释成纯锁等待时间**。

| 公开事件数 | 不读取快照（步/s） | 每 50 ms 尝试快照时（步/s） | 吞吐保持率 |
|---:|---:|---:|---:|
| 100 | 194.7 | 195.7 | 100.5% |
| 1,000 | 195.3 | 189.0 | 96.8% |
| 5,000 | 195.3 | 139.8 | 71.6% |
| 15,000 | 195.3 | 18.8 | 9.6% |

**正常频率对照（1.5 s/次）：** 15,000 条公开事件下，不读取时约 195.3 步/s，加入单观察端快照读取后约 **189.6 步/s（97.0%）**。本组只有 3 次读取，属于初步定性对照而不是高置信度生产基准。

50 ms 是刻意施加的高频压力，远高于单页面通常的 1.5 秒刷新间隔。它可用于模拟高频刷新或多个会话叠加的上界风险，**不表示线上玩家目前的每局推进速度必然降至 9.6%**。多浏览器实际负载还需真实流量或多连接压测。

## 架构归因与执行建议

- **P1 · 最小修复：** 在 `select_feed_window` 恢复有效的提前退出条件，但必须验证滚动状态、未读游标及权限行为；这是已确认的逻辑缺陷，应小范围处理。
- **P2 · 降低投影成本：** 研究先按所需事件窗口/游标取数再投影；不能随意省略供导出、回放、终局或隐私审计依赖的完整数据。通过双版本结果一致性测试保证正确性。
- **P3 · 降低持锁复制成本：** 研究“UI 专用轻量快照”或不可变的增量事件快照；注意 `snapshot()` 当前向其他使用者提供互不共享的深拷贝，不能简单把内部可变容器引用直接传给界面，否则有并发读写与信息泄漏风险。
- **验收方法：** 所有优化与同一工作负载、同一 runner 类型、相同 Python 版本的基线做前后 A/B；同时比较 P50/P95、Python 峰值分配和后台步进保持率。除性能收益外，还必须通过真人/狼队视角隐私、归档完整性、未读计数与现有完整 CI。
