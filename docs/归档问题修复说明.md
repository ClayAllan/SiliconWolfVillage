# 2026-10-24 归档问题修复说明

本轮针对三局归档暴露的问题修复代码。所有测试均使用离线响应或模拟玩家，没有发起真实模型请求；策略调整效果仍需后续真实多局对照验证。

## 已实施

- 女巫解药使用 `use_antidote` 布尔值；毒药、守护、查验、猎枪、魅惑、摄梦使用 `vote_target`；连线与交换使用 `targets`。协议校验合法目标、药品互斥、不可连守、技能发动资格及目标。解释文字不再决定动作，也不从推理中随机补目标。
- 公开发言必须有非空 `speech`。纯动作使用独立协议，不再由缺省“过。”掩盖缺字段。私密观察室按实际动作字段显示结果，不自动公开私密理由。
- 归票使用结构目标，定序只接受四种明确方向；上警、退水、交徽、抢爆和抢决斗分别校验所需字段。
- 预算耗尽时只接受完整且通过本轮校验的 JSON；截断或无效对象仍进入有限修复。修复尝试采用简短契约并关闭重复深度思考；确认与定序关闭思考并使用小预算。保留最多两次尝试、共享行动时限和连续失败熔断。
- 公共证词从公屏发言构建，不含日志中的全知角色字段或上帝记录。原话、席位、阶段和事件编号独立保存，发言者死亡或跨日不会自动抹去。记录每个请求实际展开和未展开的事件编号；篇幅上限内优先未送达信息与关键声明，未展开不代表事件不存在。
- 玩家近期决策保留结构动作和简短依据；历史大段回合提示替换为简短行动记录，避免重复发送整日发言。守墓人的真实结果加入技能状态，合法情侣关系加入相应玩家事实账本。
- 放逐、警长竞选与 PK 的票型记录 `decision_sources`，区分 `model`、`technical_fallback`、`manual_skip`、`invalid_target`。技术失票在公屏和票型图单独说明，不能解释成主动躲表态。
- 归档同时保留原始弃票率、主动弃票率和技术失票率，附分子、分母、失败行动和重试分类；旧数据缺来源时保留 unknown，能关联到旧行动记录时识别技术兜底。CSV 索引增加对应列。发生最终技术失败或人工取消的样本不再标成完全有效。
- 系统与角色提示词减少“充分推演”“孤立就是好人”“抱团极可能是狼”等重复偏置，明确事实、声明和行为假说的层级；女巫不再被强制盲毒，猎人不再被要求报复带票者，骑士允许等待，狼队比较不同刀口收益。
- 归档保存已导入的核心源码、提示词和实际运行方法的代码指纹，与归档时磁盘哈希分开，便于发现热更新版本混用。
