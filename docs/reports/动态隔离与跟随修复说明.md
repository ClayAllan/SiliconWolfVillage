# 动态隔离与跟随修复说明

实施日期：2026-10-25。项目：`F:\Github\SiliconWolfVillage`。

## 问题与依据

截图中的“狼人阵营获胜”来自上局 `54d2b656585b` 的第4天终局，结束于02:31:20。截图中正在进行的对局 `99e3e29389a4` 开始于02:31:44，02:38:10快照为第2天、6号行动、winner为空。上局150条动态与新局64条动态恰好跨过默认90条截断阈值。

原先截断提示有条件插入，正文位置随之改变；页面结尾又立即调用rerun。本机Streamlit前端只在成功完成渲染时清理旧节点，中途rerun结束不触发同样清理。这与截图中旧正文残留吻合；归档证明了信息来源，不代表旧日志被写进了新局引擎。

## 实现

- `app.py`：页面完整输出后正常返回；`live_feed.schedule_page_refresh`的后续定时片段触发下一次完整刷新，保留原1.5秒轮询间隔。页面刷新只读快照，不推进游戏。
- `game_engine.py`：公开事件统一写入`game_id`与单调递增的`event_seq`。读档时兼容补全旧日志，继续追加不会复用已有序号。
- `view_projection.py` / `live_feed.py`：只显示当前对局的事件；当前winner为空时隔离异常win行。单一视角继续过滤私密信息。过滤不会修改引擎或原归档。
- `feed_ui.py`：容器身份包含对局、视角、席位和频道；提示、正文、滚动命令分别固定占位。超过90条只替换内容，切局时更新显示身份。
- `game_archive.py`：新归档的源码哈希清单增加两个动态模块，方便后续核查版本。

## 使用方式

| 控件 | 行为 |
|---|---|
| 跟随最新：开启 | 新事件到达时滚到底部；手动上翻后，下一条新事件仍会恢复底部 |
| 跟随最新：关闭 | 保持阅读位置，显示相对已读事件游标的新动态数量 |
| 沉底一次 | 跳到当前底部并更新已读游标，不主动开启持续跟随 |
| 顶部 | 关闭跟随，跳到当前显示列表开头 |

默认只显示最近90条；“顶部”指这90条的开头。完整显示范围仍由原有完整历史设置决定，完整记录继续保存在归档中。新局/切换代入身份默认重新开启跟随；同一局普通刷新保留开关。

本机Streamlit 1.57的原生autoscroll会在用户上翻后停止粘底，因此补充了受控定向命令。命令只定位本动态容器，不滚动整个网页；每个新事件或按钮动作使用独立令牌。单次命令投递后清除，避免以后切换开关时重放。脚本不拼接玩家文本，不注册全局滚动监听器或高频定时器。
